## Objective

Connect host-resolved Playthings `tiles`, `structure` and `props` companions to the existing spatial-demand/navigation contracts without reimplementing Core/App resolver authority, then compile a bounded deterministic rectangular world candidate while keeping the active React renderer on the non-semantic Root scaffold until multi-surface presentation is separately qualified.

## Done Criteria

- Exact artifact resources and exact-schema defaults can activate Playthings spatial capabilities through the public host resolver; ancestor-schema, Root and fallback resources cannot create spatial authority.
- Qualified capability projection feeds recursive spatial demand without inspecting companion pixels for hidden topology.
- Ready demand can compile bounded rectangular Root/Surface/Structure/Container geometry with explicit wall barriers, real doors, container passages and presentation-ordered stairs validated by the existing navigation engine.
- Closing a generated door changes reachability; topology is not merely decorative.
- Historical insertion order and minimum-edge bounded packing preserve settled enclosure placement, including usable entry placement when presentation bounds grow; unresolved growth/repacking remains explicit.
- App exposes the compiled result only as a separate `spatialCandidate`; the active Root renderer remains unchanged until a later multi-surface renderer/camera gate.
- Local runtime/package/graphics qualification and isolated Core/App adapter/release qualification pass without npm publication or sibling Workspace mutation.

## Scope
