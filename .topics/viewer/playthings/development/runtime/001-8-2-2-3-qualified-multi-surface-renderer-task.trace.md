# Qualified multi-surface renderer cutover

## Objective

Promote the already-qualified exact-companion rectangular world candidate to the active Playthings presentation path without weakening the spatial provenance gate. Preserve the bounded Root scaffold as a fail-closed fallback, keep cross-surface movement explicit, and leave rendered-browser/product acceptance as separate gates.

## Done Criteria

- App selects a `presentationWorld` independently from semantic story state.
- `qualified-spatial` activates only when exact spatial capability provenance exists, the candidate/world are ready, navigation is compiled, geometry is qualified, and at least one real `tiles` or `structure` activation exists.
- Resolver availability, missing companions, blocked/partial candidates and Props-only activation retain the Root scaffold fallback.
- Scene planning records the selected renderer mode and can mark only the qualified spatial path as renderer-qualified.
- React renders the selected surface, generated enclosures, blocked cells, barriers, links, artifact markers and actors from the active presentation world.
- Cross-surface camera/actor presentation uses explicit endpoints and never draws a fictitious diagonal between unrelated surfaces.
- Local runtime/package qualification passes on the final Playthings bytes; dependency-equipped React/Vite/rendered-browser acceptance remains an explicit external gate rather than being simulated.

## Scope

Playthings-only App/runtime/React presentation work. This task does not interpret companion pixels as Tiinex spatial truth, mutate Core/App/Site, perform npm publication, certify final atlas art, complete Root Gate/fullscreen product acceptance, or take Refactor Anchor Turn 2.
