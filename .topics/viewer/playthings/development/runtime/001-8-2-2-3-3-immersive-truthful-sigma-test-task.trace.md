# Immersive truthful Playthings Sigma-test slice

## Objective

Advance the qualified multi-surface Playthings presentation into the first bounded human-testable Verse experience. Keep Tiinex truth, story-time visibility and Core/App companion resolution authoritative while Playthings owns only presentation, choreography and immersive Verse UI.

## Done Criteria

- Playthings enters and leaves host immersive mode through the supplied host contract and fills the viewport without requiring browser Fullscreen API.
- The normal Playthings presentation exposes one in-Verse Root Gate control that can return to Viewer; browser fullscreen may remain optional but is not the primary product path.
- No Playthings UI assumes schemas or companions originate in the Playthings repository. Companion selection remains exclusively delegated to the host resolver.
- Exact artifact/schema companion selection and provider precedence remain host/Core-owned; Playthings does not implement a competing resolver or use filenames/import order/repository location as authority.
- Current historical sampling continues to reveal only story records at or before the sampled historical time. Pre-discovered runtime schemas may support interpretation/resolution but are not promoted into a tech/skill discovery surface merely because runtime knows them.
- No tech-tree/skills UI is introduced until the host exposes an explicit qualified binding between a loaded Workspace schema-definition artifact and its schema declaration identity; Playthings must not infer that binding from path/title/filename.
- The existing qualified-spatial renderer and Root fallback remain fail-closed and presentation-only.
- The first Sigma test path is documented and can be exercised with the dependency-equipped source-set/browser qualifier plus manual immersive/lineage/companion review.
- Runtime/package tests pass on final Playthings bytes. Any host-level requirement that cannot be satisfied inside Playthings is returned as an explicit integration boundary rather than implemented across Core/App/Site.

## Scope

Playthings-only runtime/App-adapter/React/docs/tests needed for the first immersive Sigma experience checkpoint. This Task does not mutate Core/App/Site, create semantic schema discovery rules, infer schema-definition identity from paths, publish npm packages, claim browser acceptance without execution, or take Refactor Turn 2 ownership.

## Human Test Intent

Sigma should be able to load ordinary Workspace material in Viewer, enter Playthings, see the Verse occupy the viewport with Viewer chrome visually absent, scrub/replay truthful lineage history, observe companions through the existing resolver precedence, and leave via Root Gate back to Viewer. The test asks whether lineage and companion fusion are legible and truthful, not whether generated presentation geometry is semantic spatial truth.

## Dependencies

- [Qualified multi-surface renderer cutover](001-8-2-2-3-qualified-multi-surface-renderer-task.trace.md).
- Accepted Playthings runtime design invariants and existing story/scene historical-time contracts.
- Core/App companion resolver precedence and App Verse host callbacks supplied read-only to Playthings.
- Sigma browser/source-set execution for final human-visible acceptance; Playthings local tests do not replace that gate.
