# Playthings Scale Out

## Objective

['Select high-value exact schema defaults from demonstrated runtime gaps rather than generating graphics for every schema preemptively.', 'Use exact artifact-local companions for mods/special cases and ancestor/Root fallback for artwork without accidental capability activation.', 'Stress large histories, many branches/presences, many structures/levels, replay, seek, fast-forward and provider composition.', 'Keep generated non-final assets in graphics lineage and promote only accepted final companions to mirrored schema-default product locations.', 'Refine graphics/process/tooling only from observed production/runtime bottlenecks.']

## Scope

- ../cutover/001-playthings-host-integration-and-cutover-readiness-task.trace.md or an explicitly accepted pre-cutover scale-test exception.
- Accepted visual-production and asset-lifecycle process.
- Performance measurements from representative integration slices.

## Dependencies

- At least one materially larger real history preserves deterministic story/world behavior.
- Schema defaults and local mods demonstrate expected exact/fallback origins.
- Performance and memory stay within agreed browser/mobile budgets or have an evidence-backed optimization plan.
- No new companion/schema/artifact type is introduced without a concrete runtime need that existing contracts cannot express.

## Done Criteria

- Prioritize measured gaps.
- Expand automation/validation for companion production.
- Establish next major only when scale-out is an accepted milestone rather than by cadence.
